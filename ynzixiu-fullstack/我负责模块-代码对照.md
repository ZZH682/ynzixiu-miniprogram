## 1. 核心模块 A：交易一致性（最该指着讲）

### A1｜下单：复用待支付订单、requestId 幂等查询、条件扣库存

`backend/src/main/java/com/ynzx/server/service/OrderService.java:78-160`（节选）

```java
@Transactional(rollbackFor = Exception.class)
public Map<String, Object> createOrder(Integer userId, Integer courseId, String plan, ...) {
    // 已有待支付订单直接复用，避免重复下单反复占用库存
    Order pending = orderMapper.selectOne(new LambdaQueryWrapper<Order>()
            .eq(Order::getUserId, userId)
            .eq(Order::getCourseId, courseId)
            .eq(Order::getStatus, "unpaid")
            .last("LIMIT 1"));
    if (pending != null) {
        log.info("复用待支付订单 orderNo={}", pending.getOrderNo());
        return buildOrderResult(pending);
    }

    Order order = new Order();
    order.setOrderNo(generateOrderNo(now));
    order.setUserId(userId);
    order.setCourseId(courseId);
    order.setPlan("installment".equals(plan) ? "installment" : "full");
    order.setAmount(amount);
    order.setPaid(0);
    order.setStatus("unpaid");
    order.setRequestId(requestId);

    try {
        orderMapper.insert(order);
    } catch (org.springframework.dao.DuplicateKeyException e) {
        // 唯一索引拦截了并发重复提交
        Order exist = orderMapper.selectByRequestId(userId, requestId);
        if (exist != null) {
            return buildOrderResult(exist);
        }
        throw e;
    }
    // 下单即在事务内原子扣减库存并累加销量
    if (courseMapper.deductStock(courseId, 1) == 0) {
        throw new BizException(ErrorCode.STOCK_NOT_ENOUGH);
    }
    return buildOrderResult(order);
}
```

**逐句人话**：
1. `@Transactional` = 这一串数据库操作要么全成、要么全撤，不会留下「订单建了但库存没扣」的半成品。
2. 先查有没有 `unpaid` 订单 → 用户连点两次「下单」不会多占库存，直接把旧订单还给他。
3. `requestId` 存进订单 → 先按 `(userId, requestId)` 查已有订单（幂等快速路径），`catch (DuplicateKeyException)` 是防御性写法。⚠️ DDL 里 `idx_orders_request_id` 是**普通索引**不是唯一约束（`db/h2/schema.sql:273`），真正 UNIQUE 的是 `order_no`；并发兜底实际靠 `order_no` 唯一 + 事务内条件扣库存。别答成「唯一索引」，详见 `追问-重复支付怎么解决.md` 第 6 节。
4. 最后 `deductStock(...) == 0` 就抛库存不足；因为整段在事务里，抛异常会把刚插入的订单一起回滚。

**可以照念**：「下单这里我做了三层防重：复用待支付订单、`requestId` 幂等查询、事务内条件扣库存，`order_no` 有唯一约束兜底。扣库存失败会抛异常，订单跟着回滚，不会留幽灵库存。`request_id` 目前只是普通索引，这是我会补的一项。」

### A2｜防超卖的那一条 SQL

`backend/src/main/java/com/ynzx/server/mapper/CourseMapper.java:20-36`

```java
/**
 * 乐观扣库存：只有当库存足够时才更新成功。
 * 为什么不用"先 select 库存，再 update"？那是典型的 check-then-act 竞态：
 * 两个线程同时读到 stock=1，都通过检查，最后都执行 update，导致卖出 2 份。
 */
@Update("UPDATE courses SET stock = stock - #{qty}, sales = sales + #{qty} "
        + "WHERE id = #{id} AND stock >= #{qty}")
int deductStock(@Param("id") Integer id, @Param("qty") Integer qty);
```

**人话**：把「判断」和「扣减」合并成**一条带 WHERE 的原子 SQL**，由数据库行锁保证互斥。返回 1 = 抢到了，返回 0 = 没库存了。
**追问点**：如果在 Java 里 `if (stock > 0) update(...)`，两个线程同时读到 1，就会卖出 2 份，这叫 check-then-act 竞态。

### A3｜金额计算（最容易被要求现场读、现场改的一段）

`backend/src/main/java/com/ynzx/server/service/OrderService.java:54,177-189`

```java
private static final int INSTALLMENT_FIRST_RATIO = 30;

public int calculatePayAmount(Order order) {
    int amount = order.getAmount() == null ? 0 : order.getAmount();
    int paid = order.getPaid() == null ? 0 : order.getPaid();
    if (!"installment".equals(order.getPlan())) {
        return amount;
    }
    if (paid <= 0) {
        // 首付：向上取整
        return (int) Math.ceil(amount * INSTALLMENT_FIRST_RATIO / 100.0);
    }
    // 尾款
    return Math.max(0, amount - paid);
}
```

**逐句人话**：
- `Integer` 可能为 null → 先兜底成 0，避免拆箱时空指针。
- `"installment".equals(plan)` 把**常量放前面** → `plan` 是 null 时返回 false，不会 NPE；写成 `plan.equals("installment")` 就会崩。
- 必须写 `100.0`，写 `100` 会变整数除法，30000.3 被截成 30000。
- `ceil` 向上取整：100001 分的首付是 **30001 而不是 30000**，少收 1 分也是资损。
- 付过首付后收尾款 `amount - paid`，用 `Math.max(0, ...)` 防止负数。

**对应的验证代码**：`backend/src/test/java/com/ynzx/server/OrderServiceUnitTest.java:28-32`

```java
@Test
void installmentFirstPaymentIsThirtyPercentRoundedUp() {
    // ceil(100001 * 0.3) = 30001，向上取整避免少收
    assertEquals(30001, service.calculatePayAmount(order("installment", 100001, 0)));
}
```

**可现场改的需求**：首付 30% → 40%。改 `INSTALLMENT_FIRST_RATIO = 40`，**补一条新断言**（100001 → 40001），保留原有 4 条，再跑全量。对应 `java-basics-drill/` 的 L3。

### A4｜支付状态机、金额校验、重查、收据只插一次

`backend/src/main/java/com/ynzx/server/service/OrderService.java:196-258`（节选）

```java
@Transactional(rollbackFor = Exception.class)
public Map<String, Object> pay(String orderNo, Integer payAmount, String channel) {
    Order order = orderMapper.selectOne(...);
    if (order == null) {
        throw new BizException(ErrorCode.ORDER_NOT_FOUND);
    }
    if (!"unpaid".equals(order.getStatus()) && !"part_paid".equals(order.getStatus())) {
        throw new BizException(ErrorCode.ORDER_STATUS_CONFLICT, "订单状态为 " + order.getStatus() + "，不可支付");
    }

    int expect = calculatePayAmount(order);
    int actual = payAmount == null ? expect : payAmount;
    if (actual != expect) {
        throw new BizException(ErrorCode.PAY_AMOUNT_MISMATCH,
                "应付 " + expect + " 分，实际支付 " + actual + " 分");
    }

    // 状态机推进：用条件更新保证幂等
    int affected;
    if ("part_paid".equals(order.getStatus())) {
        affected = orderMapper.markFinalPaid(order.getOrderNo(), now);
    } else if ("installment".equals(order.getPlan())) {
        affected = orderMapper.markPartPaid(order.getOrderNo(), actual, now);
    } else {
        affected = orderMapper.markPaid(order.getOrderNo(), now);
    }
    if (affected == 0) {
        throw new BizException(ErrorCode.ORDER_STATUS_CONFLICT, "订单状态已变更，支付失败");
    }

    // 关键修复：重新查库拿到"已支付"的最新订单再结算佣金
    // 原版传的是 UPDATE 前的旧对象，paid 仍是 0，佣金算成了 0
    Order paidOrder = orderMapper.selectOne(...);
    referralService.settleAfterPayment(paidOrder);

    // 支付成功 -> 自动生成电子收据
    Receipt receipt = new Receipt();
    receipt.setReceiptNo(generateReceiptNo(now));
    receipt.setOrderNo(paidOrder.getOrderNo());
    receipt.setAmount(actual);
    receiptMapper.insert(receipt);
    ...
}
```

**逐句人话**：
1. 先校验状态：只有 `unpaid` / `part_paid` 能付。已 `paid` 的订单第二次支付 → 直接抛 `1502`，这就是重复支付冒烟断言的来源。
2. 服务端自己算应付金额，前端传了就比对，**防止前端改金额**。
3. `markPaid` 是带 `WHERE status='unpaid'` 的条件更新；`affected == 0` 说明被别人抢先改了状态，立刻停，不再往下出收据。
4. **重查 `paidOrder`**：旧对象里 `paid` 还是 0，直接拿去算佣金会算成 0。
5. 收据在支付事务里插入一次，订单号唯一，重复支付不会出第二张。

### A5｜锁为什么放在 Controller 层

`backend/src/main/java/com/ynzx/server/controller/OrderController.java:62-79`

```java
@PostMapping("/{orderNo}/pay")
public R<Map<String, Object>> pay(@PathVariable String orderNo,
                                  @RequestParam(required = false) Integer payAmount,
                                  @RequestParam(required = false) String channel) {
    var user = AuthInterceptor.requireLogin();
    Order order = orderService.getByOrderNo(orderNo);
    if (order == null || !order.getUserId().equals(user.getUserId())) {
        return R.fail(ErrorCode.ORDER_NOT_FOUND);
    }
    // 锁在事务之外：OrderService.pay 自带 @Transactional，
    // 若把锁加在事务内部，锁会在事务提交前释放，仍然可能被并发重复支付。
    try {
        return R.ok(distributedLock.executeWithLock("pay:" + orderNo,
                () -> orderService.pay(orderNo, payAmount, channel)));
    } catch (IllegalStateException e) {
        return R.fail(ErrorCode.CONFLICT, "该订单正在支付中，请稍后重试");
    }
}
```

`backend/src/main/java/com/ynzx/server/lock/RedisDistributedLock.java:47-86`（节选）

```java
public LockHandle tryLock(String key) {
    String lockKey = KEY_PREFIX + key;
    String token = UUID.randomUUID().toString();   // 释放时校验持有者
    long deadline = System.currentTimeMillis() + waitMillis;
    while (System.currentTimeMillis() < deadline) {
        // SET key token NX PX ttl —— 一条命令完成"不存在才设置 + 设置过期时间"
        Boolean ok = redis.opsForValue().setIfAbsent(lockKey, token, leaseDuration);
        if (Boolean.TRUE.equals(ok)) {
            return () -> unlock(lockKey, token);
        }
        Thread.sleep(30);
    }
    return null;
}

/** Lua 原子释放：值匹配才删 */
private void unlock(String lockKey, String token) {
    redis.execute(UNLOCK_SCRIPT, Collections.singletonList(lockKey), token);
}
```

**人话**：锁像厕所门口的牌子，事务像里面办手续。**手续没办完就开门，下一个人看到的是旧表格**，所以锁必须包在事务方法**外面**（Controller 层）。`SET NX` 保证只有一个请求能挂上牌子，`token` + Lua 保证「只删自己挂的牌子」，不会误删别人的锁。
**取舍要主动讲**：锁只解决互斥，不解决幂等。Redis 降级成本地锁后跨实例会失效，最后还是靠 A4 的数据库状态机（条件更新 + 事务）兜底；收据只在成功路径插一次，但 `receipts` 表没有 DB 唯一约束，这是可补强项。

function apiBase() {
  const m = location.search.match(/[?&]api=([^&]+)/);
  if (m) return decodeURIComponent(m[1]);
  return window.API_BASE || '';
}

let adminMode = false;
function token() {
  try { return localStorage.getItem(adminMode ? 'yz_admin_token' : 'yz_token'); } catch (e) { return null; }
}
function authHeaders() {
  const headers = { 'Content-Type': 'application/json' };
  const t = token();
  if (t) headers['Authorization'] = 'Bearer ' + t;
  return headers;
}

async function request(path, opt) {
  let res;
  try {
    res = await fetch(apiBase() + '/api/v1' + path,
      Object.assign({ headers: authHeaders(), credentials: 'omit' }, opt || {}));
  } catch (e) {
    throw new Error('后端未连接');
  }
  let body = {};
  try { body = await res.json(); } catch (e) { body = {}; }
  if (body && body.code !== undefined && body.code !== 0) {
    const err = new Error(body.msg || ('HTTP ' + res.status));
    err.code = body.code;
    throw err;
  }
  if (!res.ok && (!body || body.code === undefined)) {
    throw new Error('HTTP ' + res.status + (body && body.msg ? ' ' + body.msg : ''));
  }
  return body && body.data;
}

function mergeById(mockList, rows, mapFn) {
  if (!Array.isArray(rows) || !rows.length) return mockList;

  const idx = {};
  mapped.forEach((r) => { idx[String(r.id)] = r; });
  const seen = {};
  const out = (mockList || []).map((m) => {
    seen[String(m.id)] = 1;
    const b = idx[String(m.id)];
    return b ? Object.assign({}, m, b) : m;
