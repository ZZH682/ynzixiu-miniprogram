# 简单模块版 — 还是按同一个模板讲

> **为什么换模块**：前面的支付幂等、分布式锁、CLOB、循环依赖偏难，讲不清容易被追死。
> 这份换成本项目里**三个代码最短、最容易读懂**的模块，只用到变量、判断、循环、字符串、类与对象，
> 正好用来回答「AI 生成的项目不能代替你本人理解基础代码」。
>
> **格式完全不变**（和 `项目复盘-按模板回答.md` 一样）：
> **我负责的内容 → 遇到的问题 → 思考 → 修改 → 重新验证**，每段后面配「相关代码」和「可能的提问」。
>
> 所有代码从项目**原样摘录**，标了路径行号；讲不出精确行号就说文件名 + 方法名，别编数字。

public Integer submit(Signup signup, Integer userId) {

**逐句人话（这段一定要能自己讲一遍）**：
1. `Signup signup` 是前端传来的对象，`Integer userId` 是当前登录人（游客是 null）——**方法参数和返回值**：进去一个对象 + 一个 ID，出来一个新记录的自增 ID。
2. `getName() == null || isBlank()`：null 和空字符串是两回事，都要挡；空名字给默认值「匿名访客」，而不是让数据库存个空。
3. `matches("^1\\d{10}$")`：手机号必须 1 开头、后面 10 位数字；不合法抛业务异常，前端会收到 `code=1001`。
4. `setUserId(userId)`：游客就是 null，`mySignups` 里先判 null 再查，返回空列表 `List.of()`，不会拼出 `user_id = null` 的怪查询。
5. `source` 空时默认 `h5`，`status` 初始 `new`，`createdAt` 取当前时间——**服务端自己填，不信前端**。
6. `insert` 之后 `getId()`：主键由数据库自增回填到对象里。

### A3 遇到的问题

1. **表单可能传空名字、错手机号、超长留言** → 后台会出现一堆脏线索，招生老师没法跟进。这是设计时就预判到的。
2. **游客提交时 `userId` 是 null** → 「我的预约」查询如果直接拿 null 去拼条件，行为不可预期。
3. **冒烟脚本一开始报「留资接口 404」**（真实踩到）→ 查下来是我在测试脚本里漏写了 `/api/v1` 前缀，**接口本身没问题，是测试 URL 写错了**。
4. 留言内容不限制长度会撑爆字段 → 超过 2000 字符截断。

### A4 思考

- 「先想清楚脏数据从哪来」：全部来自前端，所以**校验放服务端**，不能只在页面上用 JS 挡一下。
- 「404 那次我没急着改接口」：先看响应码和请求 URL，发现少了一层统一前缀 `/api/v1`，和我改过的 404 归一逻辑无关。这和第 5 个缺陷一样，属于**测量工具写错，不是产品错**。
- 「null 要分两种」：没登录（userId=null）和字段没填（name=null）处理方式不同——一个返回空列表，一个给默认值。

**逐句人话**：
- `listSignups`：三个筛选条件**只有传了才加进 WHERE**，用 `if` 拼查询条件，最后按提交时间倒序。

- `csv()`：字段里如果有逗号、引号、换行，会破坏 CSV 结构 → 用双引号包起来，并把内部的 `"` 换成 `""`（CSV 转义规则）。

### B3 遇到的问题

1. **导出的 CSV 用 Excel 打开中文乱码** → 缺 UTF-8 BOM。
2. **备注里带逗号或换行会把一列拆成两列** → 需要转义。
3. **冒烟报「CSV 没有 BOM」（真实踩到）** → 我用了 `utf-8-sig` 解码，它会自动剥掉 BOM，于是怎么测都是「没有」。**是断言的测量方式错了**。
4. 非管理员直接调导出接口 → 403，需要权限判断。

### B4 思考

- 「乱码先看文件头字节，不要先怀疑编码配置」：Excel 在中文 Windows 上按本地编码解析 UTF-8 文件，加 BOM 是最省事的解法。
- 「测试报红先复核尺子」：`utf-8-sig` 是「读文件时帮我去掉 BOM」的解码器，用它来判断 BOM 存在，逻辑上就不可能通过。应改成读**原始字节**判断开头 `EF BB BF`。
- 「CSV 不是简单用逗号 join」：用户填的内容不可控，任何字段都可能含分隔符，必须统一走 `csv()` 转义。

```java
/** 选项归一化：去空格、转大写、按字符排序，使 "BA"=="AB" */
private String normalize(String s) {
    if (s == null) {
        return "";
    }
    return s.replaceAll("\\s+", "").toUpperCase().chars()
            .sorted()
            .collect(StringBuilder::new, StringBuilder::appendCodePoint, StringBuilder::append)
            .toString();
}
```

**逐句人话**：
- `answers` 是 `Map<题目ID, 考生答案>`；`answers.size()` 是总题数。
- `for (Map.Entry ...)` 逐题遍历；题目不存在就 `continue` 跳过。
- `normalize` 三步：去所有空白 → 转大写 → 按字符排序。于是 `"BA"`、`"ab"`、`"A B"` 都变成 `"AB"`，`equals` 比较内容而不是 `==` 比引用。
- 对了 `right++`，错了记错题本；整个方法一个事务，模考记录和错题要么全成要么全败。

### C3 遇到的问题

1. **多选答案顺序不一致**：考生写 `BA`，标准答案 `AB`，直接比较会判错。
2. **大小写、空格干扰**：`a b`、`Ab` 都应算对。
3. **集成测试一开始把 `/quiz/questions` 的 `data` 当 `Map` 强转报错**（真实踩到）→ 那个接口返回的是**数组**，不是对象。我的断言写法错了。
4. 科目名和题目曾对不上（种子数据里 `subjects` 名称写错）→ 页面显示的科目和题目不匹配。

### C4 思考

- 「比较之前先归一化」：不要在每个分支里写一堆 `if (a.equals("AB") || a.equals("BA") ...)`，把输入统一成一种形式再比一次。
- 「字符串必须用 `equals`」：`==` 比的是引用，只有字面量因为常量池才碰巧相等；练习册里我特意用 `new String("A")` 暴露这个坑。
- 「测试报错先看接口实际返回什么」：打印原始报文，发现 `data` 是数组，于是新增 `assertOk()` 并按 `List` 强转，**不是接口错，是断言的类型假设错了**。

### C5 修改

| 改动 | 位置 | 为什么 |
|---|---|---|
| 新增 `normalize()` 并用于判分 | `QuizService.java:173,233-242` | 顺序/大小写/空格不影响判分 |
| 集成测试按 `List` 接收 `data` | `SmokeIntegrationTest.java:140-151` | 接口返回数组，断言类型要匹配 |
| 修正 H2 / MySQL 两份 `subjects` 名称 | `db/*/data.sql` | 科目与题目对齐 |
| 题目不存在时 `continue` | `QuizService.java:170-172` | 脏题号不让整场模考崩掉 |

### C6 重新验证

`backend/src/test/java/com/ynzx/server/SmokeIntegrationTest.java:140-151`

```java
// /quiz/questions 的 data 是数组，不是对象
ResponseEntity<Map> resp = rest.getForEntity("/api/v1/quiz/questions?sid=1&page=1&size=5", Map.class);
assertOk(resp);
List<Map<String, Object>> list = (List<Map<String, Object>>) resp.getBody().get("data");
assertFalse(list == null || list.isEmpty(), "科目 1 应有题目");
Object qid = list.get(0).get("id");

        new HttpEntity<>("{\"questionId\":" + qid + ",\"chosen\":\"A\"}", json(userToken)), Map.class));
assertTrue(judged.containsKey("correct"), "应返回判卷结果");
```

- 边界用例：`"AB"` / `"BA"` / `"a b"` / `""` / `null` / 长度不等 / 全空，至少 5 组。
- 练习册 `java-basics-drill/` 的 L4 就是拿这段逻辑埋了 3 个缺陷（`<=` 越界、`==` 比字符串、null/长度不等）来练排错。

### C7 可能的提问

| 追问 | 回答要点 |
|---|---|
| `normalize` 每一步在干嘛？ | `replaceAll("\\s+","")` 去空白 → `toUpperCase()` 统一大小写 → `chars().sorted()` 按字符排序 |
| 为什么不用 `==` 比字符串？ | `==` 比引用地址；`equals` 比内容。字面量因常量池会碰巧相等，`new String("A")` 就暴露了 |
| `Map.Entry` 遍历拿到什么？ | 键是题目 ID，值是考生答案 |
| `continue` 那句干嘛？ | 题号在库里不存在就跳过，不让一条脏数据毁掉整场模考 |
| 为什么整个方法加事务？ | 模考记录和多条错题本更新要么全成要么全败 |
| 深挖：集成测试为什么报错？ | 把返回数组的 `data` 当 `Map` 强转；打印原始报文后改成按 `List` 接 |
| 深挖：如果答案是 `"ABCD"`，排序还够吗？ | 够；若要处理重复字符或乱序+重复，可改成计数比较，并补对应用例 |
| 深挖：判分性能？ | 循环里逐题查库，题量大应一次批量查出来再比；当前是演示规模 |

### C8 可现场改的小需求

「让判分忽略大小写但**保留**答案顺序」（即 `BA` 算错）→ 去掉 `normalize` 里的 `.sorted()`，补两条断言（`AB` 对、`BA` 错），跑 14 个测试。
