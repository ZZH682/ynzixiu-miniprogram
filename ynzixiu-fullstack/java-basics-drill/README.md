## 4. 四个模块的题目要求

### L1 基础语法
- `payAmount(amount, paid, plan)`：变量、`Integer` 拆箱与 null、算术与向上取整、条件分支、方法参数与返回值。
- `normalize(raw)`：循环 / 字符数组、字符串处理。项目里让多选答案 `AB` 与 `BA` 等价，就是这段逻辑。
- 重点体会：**金额单位是「分」的整数**，用 `Math.ceil` 是防止少收 1 分；`amount * 30 / 100.0` 里为什么必须写 `100.0`（写 `100` 会变整数除法）。

### L2 面向对象
补全 `SimpleOrder`：属性已有，要求写 `remain()` / `pay()` / `isPaid()`，让状态从 `unpaid → part_paid → paid` 在对象内部流转。
- 思考题：为什么 `pay()` 要自己改 `status`，而不是让外部代码改？这就是封装。
- 对照项目：`entity/Order.java` 是真实订单类，有 18 个属性，用 Lombok `@Data` 自动生成 getter/setter（见第 9 节）。

### L3 读码与修改
`payAmountV2` 是项目 `calculatePayAmount` 的简化版。**先口头回答下面三问（答案在第 5 节）**，再改代码满足新需求：
1. 这段代码在做什么？三个分支分别对应什么业务？
2. `payAmountV2(100001, 0, "installment")` 返回多少？为什么不是 30000？
3. 如果 `plan` 传 `null`，会抛异常吗？为什么？

**改动要求**：① installment 首付 30% → 40%；② 新增 `plan = "deposit"` 首付 20%；③ 其余规则不变。

### L4 排错与验证
`countCorrect` 埋了 **3 个缺陷**。按四步做，并写下来（面试时会让你边说边做）：
1. **现象**：运行时抛什么异常 / 哪组输入输出不对？
2. **排查思路**：先看什么、怎么缩小范围？（提示：异常类名 → 行号 → 变量值 → 边界输入）
3. **修复**：改完再跑。
4. **验证**：至少用 5 组不同输入检查（正常、边界、长度不等、含 null、全空）。

> 提示：自测里特意放了一组 `new String("A")`。用字面量 `"A" == "A"` 会因为字符串常量池**碰巧正确**，只有非字面量才能暴露 `==` 与 `equals` 的区别——这是面试常考的坑。

## 5. L3 口头题参考答案（先自己答再看）

1. **在做什么**：算本次该收多少钱。非分期直接收全额；分期且还没付过，收首付（总额的 30%，向上取整）；已经付过首付，收尾款（总额减已付，不小于 0）。
2. **返回 30001**：`ceil(100001 * 30 / 100.0) = ceil(30000.3) = 30001`。用「分」为单位不能四舍五入，少收 1 分就是资损，所以向上取整。
3. **不会抛异常**：写的是 `!"installment".equals(plan)`，把常量放前面调用 `equals`，`plan` 为 null 时返回 false 而不是空指针。如果写成 `plan.equals("installment")` 就会 NPE。**这是要主动讲出来的细节**。

**改法思路**：把首付比例抽成变量，`installment` 给 40、`deposit` 给 20，两个 plan 共用「付过就收尾款」的分支；其它 plan 走全额。注意 `deposit` 也会走到 `paid > 0` 的尾款分支，别只改首个 if。

## 6. L4 排查思路参考

| 缺陷 | 现象 | 排查思路 | 修复 |
|---|---|---|---|
| `i <= chosen.length` | `ArrayIndexOutOfBoundsException`，越界下标正好等于数组长度 | 看异常类名和行号 → 打印 `i` 与 `length` → 确认循环边界是 `<` 不是 `<=` | 改成 `i < len` |
| `chosen[i] == keys[i]` | 字面量测试侥幸通过，`new String("A")` 判为错 | 结果不符预期时**先怀疑比较方式**：`==` 比引用，`equals` 比内容；打印两串的 `hashCode` 与 `equals` 结果 | 用 `normalize(a).equals(normalize(b))`，顺带解决大小写/空格 |
| 未处理长度不等 / null | 数组长短不一时越界；传入 null 直接 NPE | 用**边界输入**逼出来：空数组、长度不等、含 null、全 null | 取 `Math.min` 作循环上界，比较前判空，null 数组直接返回 0 |

**排查思路的通用说法**（面试时照这个顺序说）：
> 「先看异常类型和行号定位到哪一句；再打印或断点看那一句的变量实际值；如果没抛异常只是结果不对，就用最小输入复现，再逐步加边界输入缩小范围；修完不能只跑原来那组，要用正常值、边界值、异常值各跑一遍，最好固化成断言。」

这句对应项目里的 `OrderServiceUnitTest.java`——4 个用例分别覆盖一次付清、首付取整、尾款、null 金额，就是「不同输入检查结果」的实际做法。

## 9. 一个必被追问的点：getter/setter 哪来的

项目里的 `Order.java` 用了 Lombok 的 `@Data`，源码里**看不到** `getAmount()` / `setPlan()`，但 `OrderService` 里到处在调。
如果被问「这些方法在哪定义的」，答：
> 「用了 Lombok `@Data`，编译期根据字段自动生成 getter/setter、`toString` 等，所以源码里没有但能调用；IDE 需要装 Lombok 插件才能不报错。基础练习里我特意不用 Lombok，手写getter，就是为了把属性和方法的对应关系搞清楚。」

这一句能直接证明「你本人理解基础代码」，而不只是把 AI 生成的项目跑起来了。
