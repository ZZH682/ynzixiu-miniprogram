### B. 标准版（推荐，约 550 字，项目经历为主时用）

**云南自修学校「五站合一」教育服务平台**（个人全栈项目）　`[起始月] – [结束月]`
**角色**：独立设计与开发（后端 / 前端 / 联调验证）
**技术栈**：Java 21 · Spring Boot 3.2.5 · MyBatis-Plus 3.5.7 · MySQL 8 / H2 · Redis / Caffeine · JJWT · BCrypt · Maven · Docker · JUnit 5 · 原生 JavaScript SPA

**项目描述**：基于教育行业建站方案，独立设计并实现覆盖「招生 → 交易 → 学习」全链路的 Java 后端与响应式 H5 前端。后端按领域拆分为 **9 个 Controller、11 个 Service**，设计 **33 张表**、提供 **46 个 REST 接口**，打通注册登录、预约留资、选课下单、在线支付与电子收据、章节试听与学习进度、刷题/模考/错题本、招生线索管理、经营数据导出的完整闭环，覆盖 6 条培训业务线；前端为 32 路由 SPA，通过数据同步层与后端聚合接口打通，脱离后端仍可离线演示。

**核心工作**：
- **认证鉴权**：基于 JJWT 实现用户端 / 管理端**双密钥域** Token（`yz_token` / `yz_admin_token`），`HandlerInterceptor` 统一鉴权 + `ThreadLocal` 用户上下文；管理员密码 BCrypt 哈希。
- **并发与一致性**：支付、参团、下单等写路径用 `@Transactional` 保证多表一致；下单事务内条件扣减库存防超卖；分布式锁在 **Controller 层包住事务方法**，确保锁在事务提交后才释放；Redis `SET NX` + **Lua 原子释放**，Redis 不可用时自动降级本地锁；订单以 `requestId` 幂等键 + `WHERE status='unpaid'` 条件更新推进状态机，重复支付不重复扣款、不重复出据；分期按首付 `ceil(30%)` / 尾款 `amount - paid` 计算，支付后重查最新 `paid` 再结算佣金。
- **高可用组件**：抽象 `CacheService` 支持 Redis / Caffeine 双实现并按可用性自动切换；**空值标记防穿透**、**TTL 随机抖动防雪崩**；基于 CAS + 秒级槽位实现**滑动窗口限流**拦截器（独立 `RateLimitConfig` 定义 Bean 以规避与 MVC 配置的循环依赖）。
- **业务实现**：题库判分与错题本 upsert、模考算分收敛在同一事务；多选答案归一化（`AB == BA`）；佣金 / 邀请关系以 `REQUIRES_NEW` 独立事务隔离；CSV 导出写 UTF-8 BOM 解决 Excel 中文乱码；新增门户聚合服务一次返回全站内容与学员态数据。
- **工程化**：dev（H2 + Caffeine + 本地锁）/ prod（MySQL + Redis）通过 profile 与环境变量切换，**零外部依赖即可启动**；H2 / MySQL 双份 DDL 与种子数据，prod 用 `DB_INIT_MODE=always` 首次初始化后改回 `never`；前后端同源单端口（前端由 Maven 打进 `classpath:/static/`）；Dockerfile 多阶段构建 + Compose 编排 + 一键启动脚本；统一响应体 `R`、全局异常处理、Actuator 健康检查。
- **前端**：原生 JS 实现 Hash 路由 SPA（30 业务路由 + 2 管理端路由），`api.js` 统一封装接口与 JWT 注入，`sync.js` 把后端内容聚合结果合并进静态数据、登录后回写学员态；**后端不可达时自动降级**到内置数据 + `localStorage`，页脚明示在线/离线状态。

**验证**：`mvn test` 14/14 通过（4 个纯单测验证分期金额 + 10 个 `@SpringBootTest` 随机端口集成测试，真实启动 H2 与 Spring Boot，覆盖静态站点、内容聚合、登录、留资、题库、下单支付、收据、库存销量、客服留言、管理端 CSV 导出、未知路径 404）；对最终 jar 做真实 HTTP 冒烟 46 项断言全通过（含重复支付幂等、CSV BOM、双 token 域隔离）；前端 6 个脚本 `node --check` 通过，并用最小 DOM mock 逐路由渲染 32/32 无异常、9 个离线写动作兜底正常。

## 五、高频追问 · 参考回答要点

**Q：这是真实上线的项目吗？**
> 如实说：这是基于一份商业方案做的**个人技术复刻项目**，没有真实用户和生产流量。我的目标是把交易一致性、并发控制、缓存这些后端核心问题在可运行的代码里实现并验证清楚，而不是做业务规模。所以我不讲 QPS，只讲设计取舍和怎么验证的。

**Q：为什么同时支持 H2 和 MySQL？**
> 为了让项目**零外部依赖即可启动和演示**：dev 用 H2 的 MySQL 兼容模式 + 种子数据，prod 切 MySQL。SQL 全程用标准语法，两边各维护一份 DDL 与 data.sql，我做了一次表集合 diff 确认一致。踩过的坑有三个：① H2 的 `NON_KEYWORDS` 不能包含 `SET/ORDER/GROUP`，否则 `UPDATE ... SET`、`ORDER BY` 会解析失败；自增要用 `GENERATED BY DEFAULT AS IDENTITY`；MySQL 侧列名要用反引号包住 `size/type/status/role` 这类保留字。② `settings.v` 在 H2 是 CLOB，用 `List<Map>` 取会拿到 `JdbcClob`，`String.valueOf()` 变成 `clob0: U&'...'`，Jackson 还会序列化出畸形 JSON；改成走实体的 `String` 属性由 MyBatis 用 `ResultSet#getString` 转换，H2/MySQL 行为就一致了。③ 开启 `static-path-pattern: /**` 后，Boot 3.2 找不到静态资源抛的是 `NoResourceFoundException` 而不是 `NoHandlerFoundException`，若不单独接管会被兜底异常处理器误报成 HTTP 200 + 5000，还刷 ERROR 堆栈；我补了一个 `@ExceptionHandler` 归一为真 404 + 业务码 1004。

**Q：生产库为什么默认不自动灌数据？**
> prod 的 `spring.sql.init.mode` 默认 `never`，首次部署显式设 `DB_INIT_MODE=always` 完成建表灌种子后改回 `never`。因为 schema 里带 `DROP TABLE IF EXISTS`，长期开着会在每次重启时清空真实业务数据——这是刻意做成一次性开关的。

**Q：Redis 挂了会怎样？**
> 缓存和锁都做了双实现 + 自动降级：缓存按可用性在 Redis / Caffeine 间切换，锁从 `SET NX` 降级到本地锁。降级后**单机内仍然正确**，但跨实例互斥能力会丢失——这是明确的取舍，生产上靠数据库条件更新（状态机）与事务做兜底。

**Q：支付幂等只靠锁够吗？**
> 不够，锁只解决并发互斥。我做了三层：`requestId` 幂等键（重复提交直接返回已有订单）、`WHERE status='unpaid'` 条件更新（状态机，更新行数为 0 就不再发货）、唯一的收据记录。即使锁失效或请求重放，也不会重复扣款、重复出据。另外锁放在 Controller 层而不是 Service 内部，是因为若锁在事务方法内部释放，事务尚未提交时另一个请求就能读到旧状态。

**Q：滑动窗口为什么用 CAS 而不是 synchronized？**
> 限流是全局热点路径，用 `AtomicReference` 持有窗口状态、CAS 重试提交，避免所有请求串行竞争一把锁；窗口用按秒取模的槽位数组，过期槽位在推进时清零，内存占用固定为 O(窗口秒数)。

**Q：五端都做了吗？**
> 如实说：交付的是 **PC / 手机 / 公众号三端合一的响应式 H5**，加上一套后台统一管理。小程序和 APP 需要微信审核、应用市场上架、软件著作权等外部资质，不在本地可交付范围内；但 `api.js` 与 46 个后端接口已按可复用方式抽出，替换视图层即可接入。域名备案、真实微信/支付宝支付、真实短信网关、真实视频点播同理，都是演示实现。

**Q：哪里做得不够 / 怎么改进？**（这题几乎必问，诚实答反而加分）
> 四块：① 14 个测试覆盖了主链路，但**没有做并发压测**，分布式锁、限流、防超卖目前只有功能验证，也没有统计覆盖率；② 为便于离线演示，`/content/catalog` 会下发题库答案，生产环境应移除答案字段或改为登录后按题单下发；③ 支付、短信、点播都是演示通道，未接真实第三方；④ 五端里只交付了 H5 三端，小程序 / APP 尚未接同一后端。
