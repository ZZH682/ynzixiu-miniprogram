# 针对「我遇到的问题」可能被怎么追问（含回答话术）

> **先记住一件事**：面试官追问，不是为了听标准答案，是在确认三件事——
> ① 你有没有**亲眼看到原始现象**（能不能报出原始输出/日志）；
> ② 你的判断是不是**可复现**（不是猜的、不是瞎改的）；
> ③ 改完有没有**证据**（哪条断言、跑了多少条）。
>
> 所以不管被问什么，都用这四句式收口：**现象 → 我怎么判断的 → 改了哪一行 → 用什么证明改对了**。
>
> 本清单按「5 个真实缺陷 + 4 个设计风险 + 通用追问 + 测试岗专属 + AI 相关」组织。
> 每个问题后面是**回答要点**，不是背下来的稿子；能用大白话说出来才算会。

## 0. 通用追问（几乎必问，先背这 8 条）

| 追问 | 他真正想确认什么 | 回答要点 | 证据 |
|---|---|---|---|
| 这个问题你怎么发现的？ | 你有没有验证体系 | 说清是哪一层：单测 / 集成测试 / 对最终 jar 的 HTTP 冒烟 / 逐页渲染 | `SmokeIntegrationTest.java`、`mvn test` |
| 怎么确定是 A 不是 B？ | 排除法，不是蒙的 | 「我先把原始值/日志打出来，发现 X，就排除了 Y」 | 原始报文、启动日志 |
| 改之前有没有可能改错方向？ | 你会不会试探性改代码 | 「先稳定复现、缩小到某一层、比较两种改法，再动手」 | 四步排查法 |
| 改完会不会引入新问题？ | 回归意识 | 先跑老用例 → 再跑新增断言 → 全量 → 重新打包冒烟；**保持前端契约不变** | 14/14、46/46 |
| 别的地方会不会有同样问题？ | 横向排查能力 | 「我顺手查了同类：另一种 404 异常、其他 CLOB 字段、其他配置类」 | 说明查了哪些、结论 |
| 如果重来一次怎么避免？ | 复盘能力 | 补一条回归断言 + 把检查加进冒烟清单；不是「下次小心点」 | 新增的两条集成测试 |
| 这个 bug 影响多大 / 严重级别？ | 测试岗重点 | 用户可见？数据错？监控误报？给优先级理由 | 见第 4 节 |

## 1. 缺陷 ① 404 误报成 HTTP 200 + 5000

**现象回顾**：访问不存在的路径，本该真 404，结果 HTTP 200 + `code=5000`，日志还刷 ERROR 堆栈。

### 第一层（大概率问）

**Q1：为什么状态码是 200，却说「系统异常」？**
> 因为我们约定：业务失败是 HTTP 200 + `code != 0`，只有框架级错误才给对应 HTTP 码。这个请求被**兜底异常处理器**接住了，所以 HTTP 还是 200，业务码变成 5000。这也说明它压根没走到 404 分支。

**Q2：怎么定位到是异常处理器，而不是路由配错了？**
> 就是因为 200。路由没匹配上应该是 404 或 `NoHandlerFoundException`；既然是 200 + 5000，说明异常进了 `@ExceptionHandler(Exception.class)`。我把异常类名打出来，是 `NoResourceFoundException`。

**Q3：Boot 3.2 为什么和你想的不一样？**
> Spring Framework 6.1 / Boot 3.2 起，开启 `static-path-pattern: /**` 后，找不到的静态资源抛 `NoResourceFoundException`，而不是 `NoHandlerFoundException`。我原来只处理了后者，所以漏接了。

**Q4：那把 `throw-exception-if-no-handler-found` 打开不就行了？**
> 不划算。这个开关会改变静态资源映射的行为，而**前后端同源单端口**是我刻意选的交付方式，不能为了绕开一个异常处理把架构改掉。补一个 `@ExceptionHandler` 是最小改动。

**Q5：只处理这一种够吗？**
> 我保留了原来的 `NoHandlerFoundException` 分支，再新增 `NoResourceFoundException` 分支，两个都归一到 404 + 1004；顺便把日志从 ERROR 降为 debug，不再污染告警。

**Q6：用例怎么设计？**
> 四条：① 随机不存在路径；② 归档的 `/legacy/app.html`（顺便确认旧前端没被打进 jar）；③ 断言 **HTTP 码是 404**；④ 断言 **业务码是 1004**。只断言其中一个都不够——前端只看 code，监控系统只看 HTTP 码。

### 第二层（他满意了会继续追）

- **Q7：如果前端只判 code、不看 HTTP 状态会怎样？** → 会把「页面不存在」弹成「系统故障」，用户以为网站崩了；所以两层都要断言。
- **Q8：日志为什么降成 debug？** → 用户敲错网址是正常流量，不该每次都刷 ERROR 堆栈，否则告警指标失真、真正故障被淹没。
- **Q9：404 和 403、401 在你的体系里怎么区分？** → 统一响应体 `R`，业务码 1002 未登录 / 1003 无权限 / 1004 资源不存在；HTTP 层只在框架级错误给对应状态。
- **Q10：这个问题严重级别怎么定？** → 功能上不影响主链路（P2），但监控误报 + 前端错误提示会误导用户，且掩盖真 404，所以要修。

**证据位置**：`common/GlobalExceptionHandler.java:84-104`；`SmokeIntegrationTest.java:196-210`。

## 2. 缺陷 ② H2 CLOB 序列化出畸形 JSON

**现象回顾**：灌入站点配置后，`/content/catalog` 的 `settings` 值变成 `clob0: U&'...'`，前端 JSON 坏掉。

### 第一层

**Q1：原始输出到底是什么？**
> `clob0: U&'...'` 这样的字符串。这是 **JDBC 对象的 `toString()`**，不是数据库里存的文字。

**Q2：怎么知道不是 SQL 查错表 / 字段？**
> 先看原始值：如果查错表，返回的会是另一个正常的字符串；返回对象名说明**内容没取错，是类型没转换**。

**Q3：什么是 CLOB？为什么 H2 出问题、MySQL 没有？**
> CLOB 是数据库存大文本的类型。H2 里 `settings.v` 被建成 CLOB，驱动返回 `JdbcClob` 对象；MySQL 的 `TEXT` 直接给字符串。同一份 `List<Map>` 查询在两个库上行为就不一致了。

**Q4：为什么 `List<Map>` 会拿到 `JdbcClob`？**
> MyBatis 用 Map 接结果时，按 JDBC 类型原样塞值；它不知道我想要 String，就把 Clob 对象放进来了。`String.valueOf()` 不会去读 Clob 的内容，只会调对象的 `toString()`。

**Q5：为什么不在业务层 `instanceof JdbcClob` 判断后手工读流？**
> 能修，但脏：业务代码要认识 H2 的驱动类，MySQL 还得走另一条分支，以后换库再来一遍。我选让 MyBatis 走**实体的 `String` 属性**，由框架用 `ResultSet#getString` 转换，业务层零感知、两个库行为一致。

**Q6：改了 Mapper 返回类型，前端为什么不用改？**
> 刻意的。`catalog.settings` 仍然按 `[{k,v}]` 数组下发，只是值从「对象」变成「字符串」；`sync.js` 读的还是 `row.k / row.v`。**改后端不动前端契约**，回归范围小很多。

**Q7：怎么验证的？**
> 补 6 条站点配置种子数据，对 `catalog.settings` 和 `/content/settings` 都加回归断言；H2 是每次集成测试真实跑的库。

### 第二层

- **Q8：Jackson 为什么会产出「畸形 JSON」？** → 它把 `JdbcClob` 当成普通 Java Bean 去序列化，输出一堆内部属性，前端按字符串解析就崩了。
- **Q9：项目里还有别的 CLOB 字段吗？怎么排查的？** → 我对照了 H2 / MySQL 两份 DDL 的字段类型，只把「会被前端当字符串读」的那一类走实体；长文本正文仍按各自类型处理。
- **Q10：如果生产 MySQL 一直正常，还需要改吗？** → 需要。dev 和 prod 行为不一致，就意味着**测试环境验证不了生产行为**；测试环境本身必须可信。
- **Q11：`/content/settings` 和 `catalog.settings` 为什么返回两种结构？** → 前者给需要按键取值的场景（`Map<String,String>`），后者是聚合接口里的行数组，前端历史契约是数组。两个都由同一个 `selectAll()` 派生，不会出现两份数据不一致。

**证据位置**：`mapper/SettingMapper.java:19-24`、`service/PortalService.java:161-183`。

## 3. 缺陷 ③ 限流 Bean 循环依赖导致启动失败

**现象回顾**：注册限流拦截器后应用起不来，日志给出 `WebMvcConfig → Interceptor → RateLimiter → WebMvcConfig`。

### 第一层

**Q1：启动失败你先看哪里？**
> 不看最上面，看最下面的 `APPLICATION FAILED TO START` / `caused by`。这次日志直接把 Bean 依赖链打出来了，不用猜。

**Q2：什么是循环依赖？Spring 不是能自动解决吗？**
> A 的创建依赖 B，B 的创建又依赖 A。Spring 早期允许通过提前暴露引用解决部分场景，但 Boot 2.6 起**默认禁止循环引用**，构造器注入尤其容易直接失败。所以不能指望框架兜底。

**Q3：这里具体怎么形成的？**
> `WebMvcConfig` 既注册 `RateLimitInterceptor`，又生产 `RateLimiter` Bean；而拦截器本身要注入这个 Bean，链条就绕回 `WebMvcConfig` 了。

**Q4：为什么拆配置类，而不是加 `@Lazy`？**
> `@Lazy` 能让它启动，但只是把问题延后、掩盖了「一个类承担两件事」的设计。把 Bean 定义挪到独立 `RateLimitConfig`，职责清晰，改动面也最小——**注册顺序一行没动**。

**Q5：限流为什么注册在鉴权之前？**
> 刷接口的请求应该在校验 token 之前就被挡掉，否则每次恶意请求都要做一次 JWT 解析，白白消耗。两个拦截器都挂在 `/api/v1/**`，先限流后鉴权。

**Q6：怎么证明修好了？**
> `mvn test` 能真实启动 Spring 容器，10 个集成测试全过——启动类问题的验证就是「容器能不能起来」。

### 第二层

- **Q7：如果以后又出现循环依赖，怎么快速定位？** → 看 `BeanCurrentlyInCreationException` 里的依赖链；也可以用 `/actuator/beans` 看 Bean 依赖关系。
- **Q8：限流算法为什么用 CAS 不用 synchronized？** → 限流是全局热点路径，`AtomicReference` 存不可变窗口快照 + CAS 重试，避免所有请求串行抢一把锁；数组要**写时复制**，否则 CAS 比较的是同一个引用，会「永远成功」导致计数丢失。
- **Q9：多实例部署这个限流器还准吗？** → 不准，它是单机内存实现，各限各的；生产应换 Redis + Lua。我保留了 `RateLimiter` 接口便于替换，**这是明确的取舍，不是遗漏**。

**证据位置**：`config/RateLimitConfig.java`、`config/WebMvcConfig.java:22-38`、`ratelimit/SlidingWindowRateLimiter.java:69-97`。

## 4. 缺陷 ④ 轮播图裂开

### 第一层

**Q1：怎么发现的？** → 把 32 个路由逐个渲染检查时看到首页图裂，不是接口报错。
**Q2：为什么会裂？** → 后端 `banners.to_url` 存的是「点击后跳去哪」的地址（种子数据里甚至可能是占位图路径），前端把它当站内 hash 路由用，跳不过去。属于**字段语义没对齐**。
**Q3：为什么统一回首页，不直接跳转外链？** → SPA 的 hash 路由只认 `#` 开头；外链会离开站点、行为不可预期。先收敛成可预期行为，再谈扩展。
**Q4：为什么改前端不改种子数据？** → 前端做防御更稳：以后后台运营填了奇怪的值也不会把页面搞坏。后端清洗可以做，但那是另一层的事。

### 第二层

- **Q5：真要支持外链怎么设计？** → 加 `linkType: internal | external` 字段，前端按类型决定 `location.hash` 还是 `window.open`，并对外部域名做白名单。
- **Q6：这类「数据脏导致前端崩」怎么系统性防？** → 同步层统一做类型收敛和默认值（`compact`、数组判空、`Number` 兜底），页面只读规整后的数据。

**证据位置**：`frontend/js/sync.js:144-152`。

## 5. 缺陷 ⑤ 冒烟断言自己写错（最容易被追、也最加分）

**现象回顾**：冒烟报「重复支付失败」「CSV 没有 BOM」，查下来是我自己的期望写反了。

### 第一层

**Q1：测试报红，你第一反应是什么？**
> **不是改产品代码**，先复核「标准答案」对不对。先看业务语义，再看测量方式。

**Q2：`1502` 到底是什么？**
> 订单状态冲突。订单已经 `paid`，再付一次被拒绝，**这是正确行为**。我原来写成「必须返回成功」，所以误报。

**Q3：`utf-8-sig` 为什么会吃掉 BOM？**
> 这个解码器会自动剥掉文件开头的 BOM 字节，再去解析文本。我拿它解码完再判断「有没有 BOM」，当然永远是「没有」。应该**按原始字节**判断开头是不是 `EF BB BF`。

**Q4：CSV 为什么要 BOM？**
> Excel 在 Windows 上打开 UTF-8 CSV 时，没有 BOM 会按本地编码解析，中文变乱码。这是给用户直接导出用的，必须验。

**Q5：这两处你改了产品代码吗？**
> 一行没改，只改测试脚本。**否则就会为了让测试变绿，把本来正确的功能改坏**——这是我很想主动讲的一条。

**Q6：怎么保证断言不是「假通过」？**
> 不只看 HTTP 200：幂等用例查 `receipts` 表行数、支付用例查 `paid` 金额、CSV 用例查原始字节、权限用例查拒绝码。**断言本身也要被验证**。

### 第二层

- **Q7：如果产品和测试同时错了，怎么判断谁对？** → 找第三方证据：原始响应报文、数据库直查、手工按用户动线复现，而不是在两个都可能是错的东西里打转。
- **Q8：这个「断言 bug」严重吗？** → 它不会让用户受损，但会**让质量体系失信**：要么误报浪费排查时间，要么更糟——以后有人为了过测试去改产品。所以我把这条留成案例。
- **Q9：冒烟里还有别的类似坑吗？** → 有：漏写 `/api/v1` 前缀、误用 `catalog.campuses` 字段名，都是断言/口径问题，一起修正后 46 项才全通过。

## 6. 四个「设计类风险」的追问（不是 bug，是我提前预判的）

### 幂等 / 重复支付
- **锁不就够了吗？** → 不够，锁只保证互斥。支付侧真正兜底的是 `WHERE status='unpaid'` 条件更新 + 事务；下单侧是复用 `unpaid` 订单 + `requestId` 幂等查询 + `order_no` 唯一约束。详见 `追问-重复支付怎么解决.md`。
- **`requestId` 从哪来？前端伪造怎么办？** → 前端生成并带上；服务端按 `(userId, requestId)` 查已有订单，命中就返回旧订单；伪造只会命中自己账号的旧订单，越权查他人订单在 Controller 就拦掉了。⚠️ `request_id` 目前只是**普通索引**（`db/h2/schema.sql:273`），别答成「唯一索引」。
- **支付回调重放呢？** → 同样落到状态机：状态不是 `unpaid/part_paid` 直接拒绝，条件更新影响 0 行就停，不会重复出据。
- **收据唯一怎么保证？** → 业务上只在支付成功路径插入一次，靠锁 + 状态检查 + 条件更新保证不会走到第二次；冒烟里查 `receipts` 行数。⚠️ `receipts` 表**没有 DB 唯一约束**（`schema.sql:456-468`），别答成「唯一索引」。
- **怎么做用例？** → 同一 `orderNo` 连付两次：首次 `code=0` + 1 张收据，第二次 `code=1502`，`paid` 不变、库存只扣 1 次。
- **唯一约束到底在哪？（会被翻 DDL）** → 真正 UNIQUE 的是 `orders.order_no`、`payments.pay_no`；`request_id` 和 `receipts.receipt_no` 都不是。如实讲边界，并给补法：`UNIQUE(user_id, request_id)`、`UNIQUE(order_no)`，各补一条回归断言。

### 防超卖
- **为什么条件更新是原子的？** → 判断和扣减在同一条 SQL，数据库行锁串行化；`WHERE stock >= qty` 不满足就返回 0 行。
- **返回 0 行之后呢？** → 抛 `STOCK_NOT_ENOUGH`，整个事务回滚，已插入的订单一起撤掉。
- **压测做过吗？** → **如实说没有**，只有功能验证和集成测试里的库存/销量断言；补测计划是用 JMeter 对下单、支付、领券做并发场景。

### 锁与事务顺序
- **锁放在 Service 里会怎样？** → 事务方法返回前锁就释放了，事务还没提交，另一个请求读到旧状态，仍可能重复支付。所以锁在 **Controller 层**包住事务方法。
- **为什么用 Lua 释放锁？** → 「比对 value 再删」必须原子，否则可能删掉别人续期后持有的锁；`SET NX` 抢占时带随机 token 就是为了这个比对。
- **锁超时 / 业务没跑完怎么办？** → 当前是演示级租约（10 秒）+ 等待 2 秒，没有看门狗续期；生产要补续期或改 Redisson，这是我没做的部分。
- **Redis 挂了呢？** → 降级本地 `ReentrantLock`，单机内仍正确，**跨实例互斥丢失**；靠数据库条件更新（状态机）和事务兜底，不靠缓存。这个取舍要主动讲。

### 降级
- **怎么探测 Redis 不可用？** → 按可用性在 Redis / Caffeine 间切换，配置 `auto` 探测。
- **降级后一致性靠什么？** → 不靠缓存，靠 DB 事务与状态机；缓存只影响性能。
- **怎么测降级？** → 断掉/不启动 Redis，用 dev profile 跑全链路；项目 dev 环境本来就是 Caffeine + 本地锁，46 项冒烟就是在这个形态下跑的。

## 7. 测试岗专属追问（你投测试方向，这块权重最高）

| 追问 | 回答要点 |
|---|---|
| 这几个 bug 的严重级别 / 优先级？ | ③循环依赖 = 阻断（P0，服务起不来）；②CLOB = 严重（P1，站点配置整体读不到）；①404 = 一般（P2，误导提示 + 监控误报）；④轮播 = 一般（P2，局部展示）；⑤断言 = 低（P3，不影响产品但损害质量体系可信度）。给**理由**，别只给等级 |
| 缺陷报告怎么写？ | 标题（现象 + 模块）、环境（dev/H2/Boot 3.2.5）、前置、复现步骤、预期结果、实际结果（贴原始报文/日志）、影响范围、严重级别、附件（日志截图）。① 的「实际结果」一定要写 **HTTP 200 + code=5000** |
| 回归范围怎么定？ | 按影响面分析：改了**全局异常处理器** → 所有接口的错误路径都要回归，不只测那一个 URL；改了 Mapper 返回类型 → 所有读 settings 的地方 + 两个接口；改了配置类 → 容器启动类全量 |
| 怎么用等价类/边界值设计用例？ | 404：存在的静态资源 / 存在的 API / 不存在的随机路径 / 归档路径；金额：一次付清、首付、尾款、null、100001 这种不能整除的边界；多选答案：`AB` / `BA` / 带空格 / null / 长度不等 |
| 线上才发现怎么办？ | 止损（回滚/降级）→ 保留现场（日志、报文）→ 最小复现 → 定位 → hotfix → **补回归断言** → 补监控告警 → 复盘 |
| 自动化怎么防假通过？ | 断言业务码 + 落库结果 + 原始字节；对最终交付物（jar）测，不测开发环境；冒烟脚本自身也要被复核（第 5 节案例） |
| 没做压测怎么补？ | JMeter 对下单/支付/领券做并发，观察超卖、重复扣款、限流边界；补连接池与锁等待指标；如实说明当前只有功能验证 |
| 你怎么判断一个 bug 修好了？ | 三层：该用例通过 + 老用例全过 + 对重新打包的 jar 再冒烟；缺一层我都不说「修好了」 |

## 9. 被问倒时怎么接（别硬撑、别编）

- 「这个我**当时没有验证到**，是已知边界。如果现在查，我会先看 X 的原始输出，再用 Y 复现，最后补一条 Z 断言。」
- 「具体类名我不敢确定，但我记得日志里的现象是……，代码在 `X` 文件里，我可以现在翻给你看。」
- 「这块我确实**没做**（压测 / 覆盖率 / 多实例限流），不是遗漏而是范围取舍；补的话我会……」
- 「我刚才那句说得不准，更正一下：……」——**主动更正比硬撑加分**。

**绝对不要**：编行号、编数字、把「没做」说成「做了」、把演示通道说成真实支付。

## 11. 怎么练（自问自答三轮）
