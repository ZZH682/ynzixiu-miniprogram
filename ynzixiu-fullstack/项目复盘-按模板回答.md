## 0. 先把这个项目用人话讲一遍（背景，别跳过）

### 它到底是个啥

一个「网上看课、报名、买课、刷题模考」的学校网站，加一个给招生老师用的管理后台。

**用户动线**：打开首页看课程 → 留手机号 → 注册登录（演示验证码 `123456`）→ 选课下单 → 付款 → 自动生成电子收据 → 看章节、刷题、模考 → 后台能看到报名线索、改状态、导出 Excel。

**技术上长什么样**：一个 jar 包，双击 `start.bat` 启动，浏览器打开 `http://localhost:8600/` 就能用。前端页面被一起打进这个 jar，所以**不需要 nginx、不装 MySQL、不装 Redis 也能跑**（开发态用内存数据库 H2 和本地缓存顶替）。这是我刻意做的，为了让别人拿到就能当场演示。

### 我到底干了什么（三句话）

1. 把整套网站和后台做出来：页面 + 接口 + 数据库表 + 启动脚本。
2. 把最容易出错的一段——「下单付款」——做成不会算错钱、不会超卖、不会重复出收据。
3. 把「怎么证明它是对的」也做出来：自动化测试 + 对最终 jar 的真实请求断言。

### 必须先说的边界（第一句就说，省得后面被当成吹牛）

- 这是**个人技术复刻项目**，不是公司上线系统，没有真实用户和流量，所以不讲 QPS、日活。
- 原型要求 PC / 手机 / 公众号 / 小程序 / APP 五端合一；小程序和 APP 要微信审核、应用市场上架等外部资质，**我实际交付的是 H5 三端合一 + 一套后台**。
- 真实支付、短信、视频点播都是**演示通道**（演示付款不是真扣钱）。
- 为什么这么取舍：目标是「一台电脑就能跑起来、把设计讲清楚」，而不是做业务规模。

## 1. 术语小词典（后面不会再卡壳）

| 词 | 人话 | 生活里的样子 | 项目里对应 |
|---|---|---|---|
| 接口 | 前后端约好的「一问一答」窗口 | 点菜窗口：报菜名，出菜 | 46 个 REST 接口 |
| 事务 | 一组数据库操作要么全成功、要么全撤销 | 转账：扣你的钱和加他的钱必须一起成 | 12 处 `@Transactional` |
| 幂等 | 同一件事做两次，结果和做一次一样 | 电梯按钮按两下不会来两部电梯 | 重复支付只出 1 张收据 |
| 状态机 | 订单只能按 `unpaid → part_paid → paid` 走，不许乱跳 | 洗衣机不能从「脱水」跳回「注水」 | `WHERE status='unpaid'` 条件更新 |
| 条件更新 | SQL 里带条件再改，改到 0 行就说明条件已不成立 | 最后一张票，谁抢到谁得，没抢到就返回「没了」 | `deductStock(courseId, 1)` |
| 分布式锁 | 多台机器共用的「占用中」牌子 | 厕所门口的牌子 | `SET NX` + Lua 原子释放 |
| 降级 | Redis 挂了自动换成本地方案继续跑 | 电梯坏了走楼梯，慢但能到 | Caffeine / 本地 `ReentrantLock` |
| CLOB | 数据库里存大文本的字段类型 | 大信封，**里面**才是信 | H2 里 `settings.v` |
| 循环依赖 | 两个组件互相等对方先初始化 | A 说「B 先签字我才签」，B 说「A 先签字我才签」 | `WebMvcConfig` ↔ `RateLimiter` |
| 断言 | 测试里写死的「应该是这个结果」 | 标准答案 | `assertEquals(30001, ...)` |
| 回归 | 改完把老用例再跑一遍，确认没碰坏别的 | 修完水管，把全屋水龙头都开一遍 | 14 个测试全量重跑 |
| 集成测试 | 真把服务启起来发请求，不是只测一个函数 | 整机通电试机，不是单测零件 | `@SpringBootTest` 随机端口 |
| HTTP 码 vs 业务码 | 200/404 是「这封信送没送到」；`code=0/5000` 是「这事办没办成」 | 快递签收 ≠ 事情办妥 | 两个都要对，才是真 404 |

### 第二段：遇到的问题（约 40 秒）

**人话**：分两种。一种是「我提前想到会出事」的设计风险，一种是「真的坏了」的缺陷。两种都讲：前者证明你想过，后者证明你真做过。

#### A. 提前想到的四个风险（用「抢最后一张票」来讲）

1. 网络卡，用户连点两次「付款」→ 会不会扣两次钱、出两张收据、佣金算两遍？
2. 一门课只剩 1 个名额，两个人同时点 → 会不会卖成 -1？
3. 锁如果加在事务方法**里面**，事务还没提交锁就开了 → 下一个人进来看到的还是旧状态。
4. Redis 挂了 → 多台机器各锁各的，「占用中」的牌子失效。

#### B. 联调真的坏掉的 5 个（每个都写清「像什么」和「谁先发现的」）

**① 404 误报**
现象：输错网址，本该回「没这一页」，结果回 **HTTP 200 + code=5000「系统异常」**，日志还刷 ERROR 堆栈。
像什么：前台把「没这个房间」说成「大楼塌了」，还顺手拉响警报。
谁先发现：46 项 HTTP 冒烟里「未知路径」那一条。
为什么要紧：前端只判 code，会把 404 弹成系统崩溃；监控也会误告警。

**② CLOB 畸形 JSON**
现象：站点配置读出来是 `clob0: U&'...'`，前端 JSON 直接坏掉。
像什么：要抄纸条上的字，却把装纸条的**信封标签**抄了一遍。
谁先发现：灌入 6 条站点配置后，集成测试挂了。

**③ 循环依赖，服务起不来**
现象：启动日志写着 `WebMvcConfig → Interceptor → RateLimiter → WebMvcConfig`。
像什么：A 说「B 先签字我才签」，B 说「A 先签字我才签」。
谁先发现：`mvn test` 的启动日志。

**④ 轮播图裂开**
现象：`banners.to_url` 是「点击后跳去哪」的地址，前端拿它当站内路由用，跳不过去。
谁先发现：页面渲染检查。

**⑤ 测试脚本自己错了（这条最值得讲）**
现象：冒烟报「重复支付失败」「CSV 没有 BOM」。
真相：重复付款本来就该被拒绝，业务码 1502 是**正确结果**，我却写成「必须成功」；查 Excel 中文乱码要看 CSV 开头的 BOM 字节，而我用的 `utf-8-sig` 解码会自动把 BOM 吃掉，于是误判「没有 BOM」。
像什么：**产品没坏，是我手里的尺子不准**。
谁先发现：对最终 jar 跑冒烟。

> **讲 bug 的诀窍**：一定要带上「怎么发现的」。发现方式本身就在证明你有一套验证体系，而不是碰巧看见。

### 第三段：思考（约 60 秒，最值钱的一段）

**人话**：把「我脑子里那几步」讲成故事，别只说结论。

#### 通用四步（看病类比）

1. **先看症状，不动手**：看原始响应报文 / 启动日志，不猜、不改代码。
2. **让它稳定复发**：用同一个最小输入再跑一次，确认不是偶发。
3. **缩到某一层**：框架？SQL？配置？前端？还是**我自己的测试脚本**？
4. **确认病因再开药**：至少比较两种改法，说清为什么选这个。

#### 三个主要 bug 的推理小故事

**404 那个**
我一开始以为是路由没配好。但状态码是 **200**——说明请求压根没走到「找不到页面」那一步，而是被兜底异常处理器抓走了，才返回 5000。于是把异常类名打出来，发现是 `NoResourceFoundException`：Spring Framework 6.1 / Boot 3.2 里，静态资源找不到抛的是它，不是我原来处理的 `NoHandlerFoundException`。
**结论：不是配置错，是异常映射漏了一种框架新类型。**

**CLOB 那个**
先怀疑 SQL 查错表。把原始值打出来是 `clob0: U&'...'`，这是对象的 `toString()`，不是数据库里的文字 → 说明内容没取错，是**类型没转换**：H2 把 `v` 当 CLOB，用 `List<Map>` 取到的是 `JdbcClob` 对象，`String.valueOf()` 不会去读里面的内容。
比较两种改法：在业务层 `instanceof` 判断后手工读流（脏，MySQL 还得另写一套）／让 MyBatis 走实体的 `String` 属性用 `getString` 转换（干净，两个库行为一致）。**选后者**。

**循环依赖那个**
日志已经把链条给全了，不用猜。起因是我把「生产限流器 Bean」和「注册拦截器」塞在同一个配置类里。最小改动是把 Bean 挪到新类，注册顺序一概不动。

#### 再往深想一层（这两点最加分）

- **锁 ≠ 幂等**。锁像厕所门口的牌子，只能保证「一次进一个」；事务像在里面办手续。人没办完就开门，下一个人看到的是旧表格——所以锁必须放在**门外（Controller 层）**，等事务提交完再释放。而且 Redis 降级后多台机器各锁各的，光靠锁挡不住重复请求，最后还得靠数据库 `WHERE status='unpaid'` 的条件更新和事务兜底（收据只在成功路径插一次，DDL 层并无唯一约束，见 `追问-重复支付怎么解决.md` 第 6 节）。
- **断言本身也要被验证**。测试红了先别改功能，先看是不是「标准答案」写反了。上面第 ⑤ 条我改的是测试脚本，产品代码一行没动；否则就会为了让测试变绿，把本来正确的功能改坏。

**可以照念**：
> 「我的排查顺序固定四步：先看原始响应和启动日志，不改代码；用最小输入稳定复现；再缩小到框架、SQL、配置、前端还是我自己的测试脚本；确认根因后比较两种改法再动手。比如 404 那个，状态码是 200 就说明它根本没走到 404 分支，而是被兜底异常抓走了，打印异常类名才发现 Boot 3.2 抛的是新类型。还有一条我特别想说：测试报红时我先复核期望对不对，那两次是我断言写错了，改的是测试不是产品。」

### 第五段：重新验证（约 40 秒）

**人话**：改完 ≠ 好了。得用不同办法反复证明，而且**顺序有讲究**。

#### 先说顺序（这段一定要讲）

1. 先跑**原来那批用例** → 确认没把别处改坏（这就叫回归）。
2. 再跑**针对这个 bug 新加的一条断言** → 确认这个毛病真没了。
3. 最后**全量重跑 + 重新打包 + 对最终 jar 再做一遍真实 HTTP 请求**（测交付物，不测开发环境）。

#### 五层分别查什么（体检类比）

| 层 | 像什么 | 具体断言 | 结果 |
|---|---|---|---|
| 单测 ×4 | 只查一个零件 | 金额计算，不启 Spring。最典型：100001 分的首付必须是 **30001 而不是 30000**，用 `ceil` 向上取整，少收 1 分也是资损；另覆盖尾款、一次付清、金额为 null | 全通过 |
| 集成 ×10 | 整机通电试机 | `@SpringBootTest` 随机端口真启 Spring Boot + H2 内存库，从登录一路点到 CSV 导出；本次新增 `unknownStaticPathReturnsReal404` 和 settings 回归 | 14/14（4 单测 + 10 集成） |
| HTTP 冒烟 ×46 | 按用户的方式真点一遍 | 对**打好的 jar** 发真实请求：重复支付返回 1502 且 `receipts` 只有 1 行、CSV 原始字节带 BOM、用户 token 不能访问管理端、错路径是真 404 | 46/46 |
| 前端 | 看页面 | 6 个脚本 `node --check`；最小 DOM mock 把 32 个页面逐个渲染；把后端「拔掉」模拟不可用，9 个写操作仍能走本地兜底 | 32/32、9 个动作正常 |
| 构建与交付 | 检查出厂成品 | `mvn clean package` BUILD SUCCESS、14/14；jar 内 `static/` 是新脚本、`legacy/**` 为 0（旧页面没被误打进去） | 通过 |

**结果一句话**：14/14 测试、46/46 断言、32/32 路由、9 个离线动作正常。

**诚实收尾（一定要说）**：只做了功能验证，**没做并发压测**，锁 / 限流 / 防超卖没有性能数据，也没统计覆盖率；为方便离线演示，`/content/catalog` 会下发题库答案，生产应移除或改成按题单下发。

## 3. 慢慢念的完整稿（3 分钟，句子短、少术语）

> 「先说清楚，这是我个人的技术复刻项目，不是上线系统。原型要求五端合一，但小程序和 APP 要审核上架，我实际交付的是 H5 三端加一套后台；支付、短信、点播都是演示通道。后端、前端、联调验证都是我独立做的：33 张表、46 个接口、32 个前端路由，前后端同源单端口，不装 MySQL 和 Redis 也能一键启动。
>
> 我负责三件事：把网站和后台做出来；把最容易出错的下单付款做对；把怎么证明它是对的也做出来。最花心思的是第二件——用户连点两次付款、两个人抢最后一个名额、Redis 突然挂了，这些情况下钱和名额都不能错。
>
> 过程中真踩了几个坑。第一个是输错网址，本该回『没这一页』，结果回 HTTP 200 加一个『系统异常』，日志还报警；就像前台把『没这房间』说成『大楼塌了』。第二个是站点配置读出来变成一串 `clob0:` 开头的东西，前端直接解析不了；就像要抄纸条上的字，却把信封标签抄了一遍。第三个是加了限流拦截器以后服务起不来，日志写着两个配置类互相等对方先初始化。还有一个是轮播图裂了，后台给的是跳转地址，前端当成页面路由用了。最后一条我特别想讲：冒烟脚本报『重复支付失败』『CSV 没有 BOM』，查下来其实是我自己的断言写反了——重复支付本来就该被拒绝，而我用的解码方式又自动把 BOM 吃掉了。产品没坏，是尺子不准。
>
> 这些问题我都是按同一套顺序处理的：先看原始报文和启动日志，不动代码；用最小输入让它稳定复现；再判断是框架、SQL、配置、前端，还是我自己的测试脚本；最后比较两种改法再动手。比如 404 那个，状态码是 200 就说明它没走到 404 分支，是被兜底异常抓走了，打印异常类名才发现 Boot 3.2 抛的是 `NoResourceFoundException`，不是我以为的那个。CLOB 那个，打印原始值发现是对象的 `toString()`，说明不是查错表，是类型没转换，所以我让框架按 `String` 取，而不是在业务代码里判断数据库类型。
>
> 改的时候我尽量不动架构：404 只补一个异常处理分支，没改单端口的配置；CLOB 改了 Mapper 和 Service，但下发格式不变，所以前端一行没改；循环依赖只把限流器 Bean 挪到新类，注册顺序不动；并发那边把库存判断下推到 SQL，用条件更新推进订单状态，锁放在 Controller 层包住整个事务，保证事务提交完才释放。还有两条我只改了测试脚本，产品代码一行没动。
>
> 改完不算完。我先跑原来的用例确认没改坏，再给每个缺陷补一条专门的断言，最后全量重跑、重新打包，对最终那个 jar 做 46 项真实 HTTP 请求。分层是：4 个只算金额的单测、10 个真把 Spring Boot 启起来的集成测试、46 项对 jar 的冒烟、32 个页面逐个渲染、再检查构建产物里没有旧文件。结果是 14 个测试全过、46 项断言全过、32 个路由都能渲染、9 个离线动作正常。
>
> 不足我也说清楚：没有做并发压测，锁和限流只有功能验证；为了离线演示，题库答案会一起下发，生产上应该去掉。我就是想把这些取舍和验证过程讲明白，而不是报一堆数字。」

## 5. 五张 30 秒闭环卡（救场用，每张都按模板走一遍）

**卡 1 · 404 误报**：现象 HTTP 200 + 5000 → 思考：落进兜底 handler，Boot 3.2 抛 `NoResourceFoundException` → 修改：单独 `@ExceptionHandler` 归一 404 + 1004 → 验证：集成测试 `unknownStaticPathReturnsReal404` + 冒烟同时断言 HTTP 码和业务码。

**卡 2 · CLOB 畸形 JSON**：现象 `clob0: U&'...'` → 思考：是 JDBC 对象的 `toString()`，`List<Map>` 拿到 `JdbcClob` → 修改：Mapper 返回实体 `Setting`，Service 用 `String`，前端契约不变 → 验证：补 6 条种子数据后，对 `catalog.settings` 与 `/content/settings` 都加回归断言；H2 与 MySQL 共用同一套实体映射。

**卡 3 · 循环依赖**：现象启动失败，日志给出依赖链 → 思考：配置类既注册拦截器又生产 Bean → 修改：新建 `RateLimitConfig` 只放 Bean → 验证：`mvn test` 能真实启动容器，10 个集成测试全过。

**卡 4 · 锁与事务顺序**：现象是设计评审时预判的并发窗口 → 思考：锁在事务里释放早于提交，另一请求读到旧状态；且锁不能替代幂等 → 修改：Controller 层 `executeWithLock` 包住 `OrderService.pay`，DB 侧保留状态检查 + 条件更新 + 事务（收据只插一次） → 验证：重复支付只出 1 张收据、库存只扣 1 次。

**卡 5 · 断言写错**：现象冒烟报「重复支付失败」「CSV 无 BOM」 → 思考：先复核业务语义与测量方式，发现 1502 是预期码、`utf-8-sig` 吃掉了 BOM → 修改：改测试脚本，不改产品 → 验证：修正后 46 项断言全通过，并留作「断言也要被验证」的例子。

## 6. 三种最容易讲砸的说法

1. **报数字不讲人话** → 改成「我先做了什么，为什么做」，数字放在后面当证据。
2. **只说「用了 Redis 和事务」不说为什么** → 每个技术后面补一句「因为不这么做会……」。
3. **说「改好了」不说怎么证明** → 补「我加了哪条断言、跑了多少条、对什么产物跑的」。
